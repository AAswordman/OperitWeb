# Pull Request Technical Pre-Review Redesign

## Original Situation

The existing PR workflow used the target branch tip, the contributor head, and the GitHub merge ref at the same time, without defining distinct responsibilities for the three. A stale fork would count upstream additions into the contributor diff, while the actual build only checked out head, causing path misjudgment, misattribution of old issues, and an unverified final candidate tree.

The gate also split technical checks, PR template policy, documentation hints, and the full Android build into multiple blocking statuses. A single change could receive several duplicate red lights, while any `skipped` status would be treated as success by the aggregator.

## Intent of the Change

- All technical checks run only on the merge candidate generated by GitHub
- Classification and attribution use the net diff from the candidate's first parent commit to the candidate
- Each PR keeps a single aggregated technical check status, with dedicated jobs allowed to show diagnostics separately
- PR title, body, Issue, and checklist do not participate in automatic blocking
- Android checks run in three lanes: resources, JVM, and full build
- Fork PRs receive no secrets and do not upload APKs or AABs

## Scope

- `.github/workflows/pr-check.yml`
- `.github/workflows/android-build.yml`
- `gradle/wrapper/gradle-wrapper.properties`
- `ci/script/` and `ci/test/`
- `examples/toolpkg_wasm_demo/package-lock.json`
- PR templates, CI documentation, and contribution guide

Issue auto-triage, release signing, business code, and repository rulesets are out of scope for this change.

## Expected Result

A translation change like PR #770 sees only one technical status. The candidate summary reports only the issues that PR actually introduces on the current `main`, no longer reporting historical debt in other languages, upstream documentation changes, or PR template format errors.

## Completion Status

- The old `PR Required` workflow, template policy job, and aggregator have been removed
- The new workflow keeps the `Candidate checks` aggregated status and shows dedicated jobs per scope
- Fast checks and Android lanes both use the candidate first-parent diff
- PRs do not read secrets and do not upload APK/AAB
- Gate, attribution, Markdown, and ZIP safety tests have been added
- Gradle 8.13 distribution uses official SHA-256 verification
- WASM ToolPkg uses an independent lockfile for real compilation and packaging
- Official Actions are pinned to Node.js 24 runtime versions
- ToolPkg runtime files, GitHub example generation results, and trusted build inputs are all explicitly verified
- The first online full lane passed assemble and JVM unit tests, and the four WASM module count translations flagged by Android lint were filled in
- Per repository execution constraints, no test or build commands were run this time
